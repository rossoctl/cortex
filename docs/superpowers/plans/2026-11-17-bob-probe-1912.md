# Router URL path prefix, protocol probe, and IBM Bob defaults Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A router server URL can have a path prefix, `agentop server add` finds a server's protocols and auth header by itself, and a user adds IBM Bob's gateway with `agentop server add bob https://api.us-east.bob.ibm.com/inference --main premium-ide --helper fast`.

**Architecture:** `routerconfig.Endpoint` gets a `Path` field (the prefix). The router adds the prefix to each path that it builds. `routerconfig.FetchModels` takes a new `Auth` value and tries up to four requests (rule 2). A new file `cmd/agentop/server_probe.go` sends one small request per candidate path and judges the reply by its body shape (rule 3). `serverAdd` sets the Bob defaults before the model list (rule 4).

**Tech Stack:** Go 1.26.10, standard library only. No new module dependency.

**Spec:** GitHub issue rossoctl/cortex#1912 (`gh issue view 1912 -R rossoctl/cortex`). The issue is the spec. Rule numbers in this plan (1 to 4, and 3.1 to 3.10 for the sub-steps of rule 3) are the issue's numbers. **Every implementer reads the issue rules that their task names before starting.** #1911 (merged: PRs #1933, #1934, #1936) added the `api`, `auth_header` and `headers` fields that this plan uses.

## Global Constraints

- Standard library only. `core/plugins/inferencerouter/routerconfig` stays stdlib-only and must not import `core/translate` (agentop imports it).
- Protocol names (exact): `anthropic-messages`, `chat-completions`, `responses` (`routerconfig.APIProtocols`).
- No error text from `ParseURL` or `FetchModels` quotes any part of the URL, its path, or the key.
- Run every Go command per module with `GOWORK=off`. Commits use `git commit -s`. End each commit message with `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`. Comments and commit messages in ASD-STE100 Simplified Technical English.
- No test reaches the network. Fake servers are `httptest.NewServer` on loopback.

## Decisions made for this plan (with reasons)

1. **Prefix form.** `Endpoint.Path` is the URL path with one trailing `/` removed. `""` and `"/"` give `""`. `Endpoint.URL()` returns `Scheme + "://" + Host + Path`, so agentop writes the prefix and `FetchModels` uses it with no other change. `route.target()` stays scheme and host only. Reason: `Redirect` takes no path, and the path goes through `SetRedirectPath` and `Translate`.
2. **Prefix checks.** `ParseURL` refuses a path with a `.` or `..` segment, an empty segment (`//`), or escaped characters (`u.RawPath != ""`). Error text (fixed): `the URL's path must be plain segments, with no ".", "..", empty or escaped segment`. Reason: `checkRedirectPath` refuses `..`, and the joined path must pass it. Query, fragment and user info stay refused.
3. **A key pasted as a path segment is now accepted** (`https://h.example.com/sk-SECRET`). The issue allows a path, so this is the cost. To keep it out of the logs, the router's plain-http warning in `Configure` logs `srv.target().String()` (scheme and host), not `ep.URL()`. The test row `{"https://h.example.com/sk-SECRET", path}` in `TestParseURL_QuotesNoPartOfTheURL` is removed, with the `path` const.
4. **`FetchModels` signature.** `func FetchModels(ctx context.Context, client *http.Client, ep Endpoint, a Auth) (ids []string, header string, err error)`. `header` is the auth header that worked: `a.Header` when set, else `"authorization"` or `"x-api-key"`. Reason: agentop needs it for the probe's first header (rule 3.1).
5. **`FetchModels` tries, in order** (rule 2). Round 1 uses `a.Header`, or `authorization` when it is `""`: (1) `GET <URL>/v1/models`; (2) only when (1) gave 403 or 404, `GET <URL>/v1/model/info`. Round 2 runs only when `a.Header == ""` and every status of round 1 was 401 or 403. It repeats (1) and (2) with `x-api-key`. The first 200 wins. A 200 whose body does not decode stops at once with the error `the server's model list is not an OpenAI-style list of models`. Reason: the server answered, so a wrong shape is not an auth problem.
6. **`/v1/model/info` shape** is `{"data":[{"model_name":"..."}]}`. Empty names are skipped and repeated names are kept once, in first-seen order. Reason: LiteLLM lists one `model_name` for each deployment.
7. **`FetchModels` error on no 200:** `the server answered <s1>, <s2>, ... to its model list`, with each status in the order tried. No path in it. Reason: the existing test refuses `/v1/models` in an error text.
8. **New routerconfig helpers.** `func SetAuth(h http.Header, name, key string)`: `name` `""` or `authorization` (case ignored) sets `Authorization: Bearer <key>`; any other name sets `<name>: <key>`. `func HeaderOf(m map[string]string) http.Header`: nil for an empty map, else each pair through `Header.Set`. `Configure` uses `HeaderOf` in place of its own loop. Reason: one place for both the router and agentop.
9. **The probe is skipped when `--api` is given** (rule 3.8). Then `auth_header` is what the user gave, or the Bob default, or nothing. A given `--auth-header` (or the Bob default) is **fixed**: `FetchModels` gets it as `a.Header`, and the probe does not try the other header.
10. **Candidate paths, in order.** `anthropic-messages`: `/v1/messages`, `/messages`, `/anthropic/v1/messages`. `chat-completions`: `/v1/chat/completions`, `/chat/completions`. `responses`: `/v1/responses`, `/responses`. Protocols run in `APIProtocols` order. For one protocol the probe stops at its first served candidate.
11. **Probe requests.** `POST <ep.URL()><candidate>`, `Content-Type: application/json`, the server's `headers`, and the key through `SetAuth`. Anthropic also sends `anthropic-version: 2023-06-01`. Bodies (exact, `M` is the resolved main model):
    - anthropic-messages and chat-completions: `{"model":M,"max_tokens":1,"messages":[{"role":"user","content":"ping"}]}`
    - responses: `{"model":M,"max_output_tokens":16,"input":"ping"}`
    The probe reads at most 64 KiB of each reply.
12. **Served** (rule 3.3): status 2xx and a JSON object body with `"type":"message"` (anthropic), a `choices` array (chat), or an `output` array (responses). Every other reply is not served. On 401 or 403, when the header is not fixed, the probe sends the same candidate once more with the other header (`authorization` ↔ `x-api-key`). The last reply of a candidate is its result.
13. **When nothing is served** the command stops with exit 1 and writes nothing (rule 3.6). When every candidate's last reply has the same status and the same first 512 bytes of body, the message is: `every path answered <status>: <body text>. The model or the key is wrong, not the path.` Else: `no path tried served a protocol; give the protocols with --api <protocol>=<path>`. The command prints: `agentop server add: could not find which protocols <name> serves: <message>`.
14. **Which `auth_header` the probe writes** (rule 3.5). Each served protocol has the header that worked. The usual header is `x-api-key` for `anthropic-messages` and `authorization` for the other two. When the header is fixed, it is written as given. Else, when every served protocol worked with its usual header, nothing is written. Else, when all served protocols worked with one header `H`, `H` is written. Else the command stops: `the server takes a different auth header for each protocol; give --auth-header and --api`. Reason: the router sends one `auth_header` for every protocol, and with none it sends the agent's header, which is the protocol's usual one.
15. **Probe output.** For each served protocol, sorted by name, one stdout line `api <protocol> → <path>`. When the probe writes `auth_header`, one more line `auth_header → <name>`.
16. **Probe timeouts.** The client is `routerconfig.NewModelsClient()` with `Timeout` set to 60s (a local server can load the model on the first request). The whole probe has 60s for each candidate path (`probeTotal`), 7 minutes in all.
17. **Bob defaults** (rule 4). When `strings.HasSuffix(ep.Hostname, ".bob.ibm.com")`: `models.AuthHeader = "x-api-key"` when `--auth-header` was not given, and `models.Headers["User-Agent"] = "bob-shell"` when no `--header` name equals `User-Agent` with case ignored. No message about it. Both are written to the config as fields that the user gave.
18. **Test seams.** `serverModels` becomes `var serverModels = func(s routerconfig.Server) ([]string, string, error)`. New `var probeServer = probeAPI`. `stubServerModels` in `cmd_server_test.go` also stubs `probeServer` to return `(nil, "", nil)`, so every existing `serverAdd` test writes what it writes today. The new end-to-end tests set both vars back to the real functions.
19. **One PR.** The total estimate is about 1,350 counted lines.

Facts to write (all from this plan):
- `url` is `scheme://host[:port][/path]`. A path is a prefix. The router puts it before each path it builds: a captured request's path and a path from `api`. A request sent to the server's own host keeps its own path, so the prefix is never added twice. A trailing `/` is dropped. A `.`, `..`, empty or escaped segment, a query, a fragment and user info are refused. Server identity stays the host (and the port on a loopback host).
- The model list: `GET <url>/v1/models` first. On 403 or 404, `GET <url>/v1/model/info`, which reads `data[].model_name`. With no `auth_header`, when these give 401 or 403, the two requests are sent again with `x-api-key`. The server's `headers` go on each request.
- `agentop server add` with no `--api` probes the server. For each protocol it sends one request (`max_tokens: 1`, or `max_output_tokens: 16` for `responses`, text `ping`, the main model) to `/v1/<p>` and `/<p>`, and `/anthropic/v1/messages` for `anthropic-messages`. Here `<p>` is `messages`, `chat/completions` or `responses`. A path is served only when the reply is 2xx and its body has the protocol's shape. It writes each served protocol to `api`, and prints `api <protocol> → <path>`. On 401 or 403 it tries the other auth header once, and writes `auth_header` only when a protocol needed a header that is not its usual one. When no path serves, the command stops and writes nothing. `--api` skips the probe. `--auth-header` fixes the header. The probe runs only in `server add`: run the command again to probe again. Each request costs a few tokens.
- IBM Bob: for a host that ends in `.bob.ibm.com`, `server add` sets `auth_header: x-api-key` and `headers: {User-Agent: bob-shell}` unless `--auth-header` or a `--header User-Agent=...` is given. Use a static Bob API key from Bob's settings. Example: `agentop server add bob https://api.us-east.bob.ibm.com/inference --main premium-ide --helper fast`, then `agentop server use bob --agent claude-code`.

# Bob Subagents and Subtasks in the Root Session — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** File each Bob child task (subagent or subtask) in its root task's session, give its rows a `subagent` id and a kind, and show it as a block (subagent) or a labeled section (subtask) in agentop and as an agent row in the timeline.

**Architecture:** Rule 1 is in `session.IDHeaderFrom`: when `X-Task-Id` names the session and `X-Parent-Task-Id` is valid, the session id is the parent id. Rule 2 is in `pipeline.Context.resolveSubagents`: a Bob child's own `X-Task-Id` becomes `Subagent()`. Rule 3 is a new `SubagentKind` field on `SessionEvent`, which the session-event builders fill from the request's tool list. The timeline and agentop already group rows by `Subagent`; they only add the subtask label and the open-by-default section.

**Tech Stack:** Go 1.26.10, modules `core/` and `cmd/agentop/`.

**Spec:** https://github.com/rossoctl/cortex/issues/1803 (the issue body is the spec; rules 1–7 are quoted by number below).

## Global Constraints

- Every rule acts only on a header that Bob sent. No rule guesses (no matching by time).
- Bob root tasks: the session id stays `X-Task-Id`.
- `X-Parent-Task-Id` is NOT added to `session.id_headers`. Rule 1 applies only when `X-Task-Id` gave the id.
- `X-Parent-Task-Id` is client-asserted and unauthenticated. It is a grouping key, never a principal.
- Claude Code attribution and every other client: no change.
- Header-less `router`/`security` calls: no code change (rule 4). They get no subagent id.
- Cost: no new code (rule 7).
- Header constants use canonical HTTP casing (see `session.BobSessionHeader`'s comment).
- New wire field is `omitempty`, for version skew in both directions.
- Commits: `git commit -s`, and end the message with `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`. No `Co-Authored-By`.
- `docs/agents/bob.md` changes in the same PR (the issue does not close on code alone).

## Decisions (made here, with the reason)

1. **Constants live in `core/pipeline/subagent.go`:** `BobTaskIDHeader = "X-Task-Id"` and `BobParentTaskIDHeader = "X-Parent-Task-Id"`. `session.BobSessionHeader` becomes `= pipeline.BobTaskIDHeader`. Reason: `session` imports `pipeline`, so `pipeline` cannot import `session`; this is the same placement `ClaudeCodeAgentIDHeader` uses.
2. **Rule 2 reads headers only, not the naming header.** Condition: `X-Claude-Code-Agent-Id` gave no id, `X-Task-Id` and `X-Parent-Task-Id` both pass `subagentHeader` (trim SP/HTAB, `validSubagentID`), and the two values differ. Reason: `Subagent()` is memoized at `ResolveClient`, and not every listener pins `NamingHeader()` before that call (reverseproxy, extproc). A request that sends both a Claude Code session header and a Bob child pair is not a shape any client sends.
3. **Field name and values:** `SessionEvent.SubagentKind string`, JSON `subagentKind,omitempty`; values `model.SubagentKindSubagent = "subagent"` and `model.SubagentKindSubtask = "subtask"`, aliased in `core/pipeline/model_alias.go`. Set ONLY on a Bob child's rows; empty on Claude Code rows and everywhere else. Reason: only Bob's kind is known from the wire; Claude Code's kind is `inference.agentRole`.
4. **Kind is computed per row, not memoized:** `Context.SubagentKind()` reads `c.Extensions.Inference.Tools` each time. Reason: the inference parser runs after `ResolveClient`, so a memo at that time would never see the tool list. Every builder in `sessionevent.go` that sets `Subagent` also sets `SubagentKind`, so a response row has the same kind as its request (same `pctx`). With no inference parser in the pipeline, the kind is `subagent`; documented.
5. **agentop subtask = the existing block, labeled `subtask <id>`, open by default.** Reason: the parent sends nothing while a subtask runs, so the subtask's rows are contiguous, and a block anchored at its first row is "a labeled section of the main conversation, at its place in time". It stays collapsible with Enter. A subagent block keeps today's default (collapsed) and gets the label `subagent <id>` when no harvested metadata names it.
6. **Timeline subtask label:** `Agent.Label = "subtask " + shortID(id)` and `Agent.Type = "subtask"` when any request of that agent has `SubagentKind == "subtask"`. A Bob subagent keeps today's `"subagent " + shortID(id)`. No spawn linking to `spawn_subagent`/`start_subtask` calls: the tool result naming the child id is not verified on the wire, and the issue forbids guesses.
7. **Fixture is hand-written, not live data.** Reason: live session payloads hold raw prompts. It copies the shape of the Bob IDE run (root, 1 subtask, 2 parallel subagents, 1 header-less `router` call, interleaved).

## Review Focus

1. `X-Parent-Task-Id` equal to `X-Task-Id` (a client that names itself): the row stays in its own session as a root, with no subagent id. Test in Task 1 and Task 2.
2. A parent id that `validHeaderSessionID` accepts and `validSubagentID` refuses (129–256 bytes, or a Cf rune such as U+202E): rule 1 files the row in the parent, rule 2 gives no subagent id, so the row reads as the root's own. Accepted (Bob ids are 36-byte UUIDs); pinned by a test in Task 1 so the behavior is deliberate.
3. A header-less `router` call between two parallel subagents' calls: client affinity must file it in the root, not a child. Rule 1 makes every claim name the root. Test in Task 2.
4. A response row and a denied row of a subtask must carry `subtask`, not empty: agentop reads the kind from any row of the block. Test in Task 1 (`sessionevent` builders).
5. `view=summary` must keep `subagentKind` (scalar, struct copy keeps it), or agentop never sees a subtask. Test in Task 1 (bump the field count and assert the value).

# agentop TUI polish (#2015) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every agentop pane color, weight and frame glyphs, with no change to what agentop does or shows.

**Architecture:** All new styles are package-level values in `cmd/agentop/tui/styles.go`. Table cells stay plain text; the vendored `tui/table` gets a per-cell style hook, zebra rows, a selection bar and a per-rune glyph map, all applied after a cell is cut to width. Chrome lines (titles, hints, band, drawer, detail, timeline, usage) are styled by text-preserving helpers that only wrap substrings of the plain line in styles, after every cut or fit step.

**Tech Stack:** Go 1.26.10, Bubble Tea v1, Lip Gloss v1.1.0, `github.com/charmbracelet/x/ansi`, `github.com/muesli/termenv` v0.16.0 (all already in `cmd/agentop/go.mod`; add no dependency).

**Spec:** issue #2015 (`gh issue view 2015 --repo rossoctl/cortex`). Read it in full before you start a task. Where this plan and the issue differ, the issue wins, except for the decisions listed under "Decisions".

## Global Constraints

- **Plain text does not change.** Under the Ascii profile (what `go test` gets) every pane renders byte-identical text to `main`. Under a color profile, `ansi.Strip` of the output equals the Ascii output except: (a) each key hint `[k]` (no space inside the brackets) on a hint line becomes ` k ` (same width); (b) the selected table row's first column (a blank pad) becomes `▌`.
- **Do not edit an assertion in an existing test.** Only exception: a test that forces a color profile and checks a `[k]` hint or the first column of the selected row may change to the new text. Every other existing test passes with no edit. If one fails, the change is wrong.
- Keep `renderRow`'s run split: with no cell style on a cell, its text and its fill stay ONE run in the row style (`rowLook` in `tui/search_test.go`, `TestSetSearch_TheCursorRowKeepsItsStyleAfterAHighlight` in `tui/table/search_test.go`). With a nil hook, zero `Alt`, zero `Bar` and an empty `Glyphs`, table output is byte-identical to `main`.
- **Widths do not change.** `lipgloss.Width` of every rendered line equals `main`. Never cut or pad a styled string with `runewidth.Truncate`, `runewidth.FillRight` or `len`. Style after those steps. ANSI-aware cuts (`truncToWidth`, `ansi.Truncate`, `lipgloss.Width`) may run after styling, as `fitStatusLine` and `detailFixedLine` do; keep their current order.
- **Table cells keep no ANSI.** `TestSessionsRows_CarryNoANSIUnderAForcedColourProfile` stays. Per-cell color is added only inside `tui/table`.
- Search: `Styles.Match` / `Styles.CurrentMatch` draw over the cell color. `Styles.Marked` keeps its warn ink over the column ink. The selected row keeps `colorSelectedBg` and bold, and column inks show through.
- A cell style sets only foreground and bold. Never `Reverse`, never `Background`.
- Each new color is a `lipgloss.AdaptiveColor` in `styles.go`, next to the existing palette.
- Under Ascii, key hints keep their brackets and the selected row has no `▌`.
- No `lipgloss.NewStyle()` per cell in new code. Build styles once as package-level values. The existing `NewStyle()` calls in `renderRow` and `headersView` may stay.
- Non-goals: no new information, keys, panes, columns, flags, config fields or preferences; no change to row counts, `layout()` reservations or which hint survives a narrow terminal; no tab bar; no Bubble Tea v2 / Lip Gloss v2.

## Decisions (made here, with the reason)

1. **Hook signature.** `table.WithCellStyle(f CellStyleFunc)` option plus `(*Model).SetCellStyle(f CellStyleFunc)`, with `type CellStyleFunc func(row Row, col int) lipgloss.Style`. `col` is the index into the row's cells (also the column index for a full row). Reason: the issue names this shape; panes reinstall the hook on each rebuild because column sets change at run time.
2. **"No cell style applies"** means the returned style has no foreground (`GetForeground()` is `lipgloss.NoColor{}`) and is not bold. Reason: a cell style may set only those two, and `lipgloss.Style` is not comparable.
3. **Multi-color cells use a glyph map**, `Styles.Glyphs map[rune]lipgloss.Style`. Inside a cell that HAS a cell style, a rune found in the map is drawn in that glyph style (with the row style's background and bold over it), not the cell style. Cells with no cell style ignore the map. `tui` sets `▕ ▏ ↑ ↓` to `styleDim` and `▸ ▾` to accent. Reason: the CTX gauge brackets, the BYTES arrows and the Agents `▸`/`▾` need a second color inside one cell, and a per-rune lookup needs no new API per pane. Accepted limit: the gauge's one-eighth block is the same rune as its closing bracket (`▏`, `sessions_context.go:154`), so a fill under one eighth of a cell draws dim. Write this as a `shortcut:` comment.
4. **Column identity.** Each pane builds a `[]cellKind` (or `[]eventColumnID` for Events) parallel to the columns it hands the table, at the same place it builds them, and installs a hook that closes over it. Hidden columns keep their index (width 0 is skipped by the table), so the slice stays parallel. Never match header text.
5. **Agents top-level names.** `rebuildAgentsTable` fills a `map[string]bool` of the cell-0 labels it adds with `kind` `agentRowAgent` or `agentRowHeading`; the hook bolds cell 0 when the row's cell 0 is in that map. Reason: the hook gets the row, not its index, and sub-row labels differ by their indent.
6. **ACTION groups.** Strip one trailing `*` first. `modify` accent; `deny` error; `tunnel` dim; `—` dim (the dash rule); every other value (`allow`, `observe`, `""`, unknown) muted. So `deny*` is error and `allow*` muted. Reason: the `*` marks a shadow verdict of the same verb; a would-be block is what a rollout reader looks for.
7. **STATUS groups.** `2xx` and `ok` → ok; `4xx` and `running` → warn; `5xx`, `lost`, `error` → error; `1xx`, `3xx`, `n/a` (`importedNA`), `""` and anything else → muted; `—` dim.
8. **Drawer controls line.** `[a]`, `[w]`, `[$]` become chips (` a `, ` w `, ` $ `). The selected axis keeps its brackets and is drawn as `styleSeg.Render("[model]")`. Reason: rule 1 allows only key chips to change text, and `[model]` is not a key.
9. **Detail summary.** Style the plain `m.detailSummary` with a text-preserving helper (split on ` · `): ` · ` dim, a part that `statusGroup` classifies as a status (a 3-digit number or `lost`) gets the STATUS style, a part starting with `$` or `~$` is bold. Then `truncToWidth` as today. Reason: no change to where the summary is built.
10. **Selection bar.** Drawn only when `lipgloss.ColorProfile() != termenv.Ascii` and `Styles.Bar` sets a foreground. The first shown cell renders with `PaddingLeft(0)` and is prefixed by `Bar.Inherit(row).Render("▌")`. Width unchanged.
11. **Live check** with `expect` against the local proxy is for a human (it runs against the user's real service). See "For a human after review".

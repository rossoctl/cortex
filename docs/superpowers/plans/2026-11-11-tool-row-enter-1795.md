# Enter on a Tool Row (#1795) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In agentop's events table, `Enter` on a tool row opens the exchange that holds the tool's call and its output, with the detail cursor on that call.

**Architecture:** All work is in `cmd/agentop/tui`. Task 1 finds the target exchange from the events that agentop holds (spec rule 1), sets the header number (rule 3), and opens the detail pane. Task 2 adds a pending "aim" that `showDetail` applies when a render first contains the call (rule 2), and the docs.

**Tech Stack:** Go 1.26.10, Bubble Tea, the agentop detail tree (`detail_tree.go`).

**Spec:** GitHub issue rossoctl/cortex#1795, section "Spec (v1)". Read it before each task.

## Global Constraints

- agentop only (`cmd/agentop/tui`, `cmd/agentop/README.md`). No server or API change. No new API field. Do not change `previewMax`.
- No new dependency. Do not change `nestToolBlocks` or `groupEarlier`.
- One PR.
- Comments and docs in ASD-STE100 Simplified Technical English.

## Decisions made for this plan (with reasons)

1. **The target row comes from a fresh pass over `m.events[m.selectedSess]`**: `buildEventRows` → `computeEventPairs` → `mergeExchanges`, the same three calls as `rebuildEventsTable`. Reason: rule 1 says "all rows of the session that agentop holds"; `m.visibleRows` drops hidden and filtered rows.
2. **The cursor target is found in the built tree, not computed as a string.** `groupEarlier` moves earlier messages to `request.inference.messages[<k][i]`, and `nestToolBlocks` deletes `toolUseIds` before the tree is built. So the message index comes from the held event (`Inference.Messages[i].ToolUseIDs`), and the node is the i-th message of the tree's `messages` node, with the group's kids counted first. Reason: one walk is correct for both grouped and ungrouped messages.
3. **The aim applies only while the cursor is still at the top** (`detailCursorPath == "" && detailCursorOff == 0`), and it is cleared when it applies, on a detail cursor key, and on a fold toggle. Reason: rule 2.4 (a reader move is never undone) with no extra state.
4. **Rule 2.2 picks the response's `toolCalls[t.Pos]` when its `id` equals `t.ID`, else the first entry with that `id`.** Reason: `Pos` already separates two calls with one reused ID (`tool_rows.go`).
5. **Header number:** the `#` cell of the target row when it is in `m.visibleRows` (matched by `keyOf`), else the session-wide number from `computeEventPairs`, else `""`. Reason: rule 3, and a block member's `#` counts inside its block.
6. **Esc needs no new code.** The events table does not rebuild while the detail is open, and the Enter handler does not move the events cursor. Task 1 pins this with a test.

## Review Focus

1. A tool whose `End` was clamped up to its `Start` (`tool_rows.go`, "clamped up to the call's Start"): no request has `At == End`, so rule 1.2 must apply. Test in Task 1 (`clamped end`).
2. A target message inside the "earlier messages" group (`messages[<k]`): the group fold must open. Test in Task 2 (`TestToolEnter_AimInEarlierGroup`).
3. A details search reveal and the aim at the same time: the first one that moves the cursor wins, and the other does nothing. Test in Task 2 (`TestToolEnter_SearchKeepsQuery`).
4. A response that streams in while the detail is open (`fillDetailResponse`) must not move the cursor back to the aim after the reader moved. Covered by `TestToolEnter_ReaderMoveHolds`.
5. A linked bucket's events in one session (Seq counts from 1 per bucket): rule 1.1 matches on time first, so this is safe. No new test; reviewers check rule 1.2 compares `eventSession` too.

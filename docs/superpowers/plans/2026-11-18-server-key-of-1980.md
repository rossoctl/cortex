# `agentop server use` and `reset --key-of` (#1980) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user can send the new sessions that send one server's key to a different server from the shell, through the `inference-router`'s `key_routes:` map. `agentop server` shows the entry. `agentop server remove` refuses a server that an entry names.

**Architecture:** A new `servers.KeyRouteChanges(from, to string) []edit.ConfigChange` writes or removes ONE key of `key_routes:`. `serverUse` and `serverReset` get a `--key-of` flag beside `--agent`, and call `runServerWrite` with those changes. `serverRemove` gets one more refusal. `serverList` adds `its key → <server>` to the agents cell.

**Tech Stack:** Go 1.26.10. Module `cmd/agentop` only. No change in `core/`.

**Spec:** issue rossoctl/cortex#1980 (part C1 of #1975). Read it with `gh issue view 1980 --repo rossoctl/cortex`. Part B (#1979) is merged into the base of this plan: `routerconfig.Config.KeyRoutes map[string]string` (JSON `key_routes`) exists, and `routerconfig.Decode` refuses an entry whose key or value is not a listed server. Its plan is `docs/superpowers/plans/2026-11-18-key-selects-server-1979.md`. C2 (the TUI) is NOT in this plan.

## Global Constraints

- A key is never shown. agentop names a key only by its server's name.
- `key_routes:` is one hop only. With `{team-b: team-a, team-a: team-c}`, team-b's key goes to `team-a`. agentop does not follow or refuse chains.
- Write per key, never the whole map (same reason as `servers.AgentChanges`: a concurrent write for a different key must not be reverted).
- Tests assert on substrings, as the existing tests in `cmd_server_test.go` and `cmd_server_write_test.go` do.
- Comments and docs in ASD-STE100 Simplified Technical English. Commits use `git commit -s` and end with `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`.
- Go commands run from `cmd/agentop` with `GOWORK=off`.

## Decisions made in this plan

1. **`KeyRouteChanges(from, to)` returns one change.** `Chain: "outbound", Plugin: PluginName, Path: []string{"key_routes", from}`, as `SessionChanges` does. When `to == ""` or `to == from`, `Value` is nil (a removal). Else `Value: edit.ScalarValue(to)`. Reason: the issue says `use X --key-of X` removes the entry, and a nil `Value` removes a key (`edit/pluginconfig.go`). A removal of a key that is not in the file is a no-op, so the writer reports `WriteUnchanged`.
2. **Flag text.** `--key-of` help: `the server whose key the new sessions send, such as team-b`. Reason: it names a server, never a key.
3. **Argument errors (exit 2).**
   - `use`: when both `--agent` and `--key-of` are set, print `agentop server use: --agent and --key-of are exclusive; give one`. When neither is set, or the positional count is not 1, print `agentop server use: want a server and an agent or a key: agentop server use <name> --agent <agent> | --key-of <server>`.
   - `reset`: same two messages with `reset` and `agentop server reset --agent <agent> | --key-of <server>`, positional count 0.
   - The `--key-of` value goes through `routerconfig.CheckName` first (exit 2), as the server name does. Reason: the same check as every other server name, before the config is read.
4. **Unknown names (exit 1).** After `readRouter`, each of the two names must be in `c.Servers`. A missing one prints the existing form: `agentop server use: no server named <n><configuredServers(c)>. Add it first:\n  agentop server add <n> <url>`. `reset --key-of <n>` with an unknown `<n>` prints `agentop server reset: no server named <n><configuredServers(c)>` (no "Add it first": reset adds nothing). Reason: the issue says each name must be a configured server.
5. **Messages for `use --key-of` (from = `--key-of`, to = the positional server).**
   - `to != from`: done `New sessions that send <from>'s key → <to>.`, unchanged `New sessions that send <from>'s key already go to <to>.`
   - `to == from`: done `New sessions that send <from>'s key → <from>.`, unchanged `New sessions that send <from>'s key already go to <from>.`
   - live: `runningSessionsStay`. note: `routerInactive(cfg, path)`. Reason: same shape as `--agent`.
6. **Messages for `reset --key-of <from>`.** When `c.KeyRoutes[from] == ""`, print to stdout `<from>'s key is not routed to another server; nothing to change.` and exit 0 without a write (as `reset --agent` does). Else done `New sessions that send <from>'s key go to <from>.`, live `runningSessionsStay`, unchanged the same "nothing to change" line.
7. **`remove <s>` refusal.** Order in `serverRemove`: after the "only server" check and BEFORE the `sessionsOn` check. For every `key_routes:` key `k` (sorted) where `k == s` or `c.KeyRoutes[k] == s`, collect `k`. When there is at least one, print to stderr:
   ```
   agentop server remove: key_routes.<k>: <v> names <s>; remove the entry first:
     agentop server reset --key-of <k>
   ```
   One `key_routes.<k>: <v> names <s>` clause per entry, joined with `, `, then one `agentop server reset --key-of <k>` line per entry. Exit 1, no write. Reason: the issue asks that the message names the entry and the command that removes it; `reset --key-of <k>` removes the entry on either side. Before the session and agent checks, because the config validation refuses a removal while an entry names `<s>` in any case, so it is the first fix.
8. **Listing.** A new helper `agentsCell(c routerconfig.Config, server string) string` in `cmd_server.go` returns `strings.Join(agentsOn(c, server), ", ")`, and when `to := c.KeyRoutes[server]; to != "" && to != server`, appends `its key → <to>` (joined with `, ` when agents are also there). `serverList` calls it in place of `strings.Join(agentsOn(c, name), ", ")`. Reason: the issue names the agents cell. It is the last cell, so `text/tabwriter` alignment (it counts runes) does not change.
9. **Usage text** (`serverUsage` in `cmd_server.go`) gets two lines after the `use` and `reset` lines:
   ```
     agentop server use <name> --key-of <server> [--config PATH]
     agentop server reset --key-of <server> [--config PATH]
   ```
   and this paragraph after the paragraph that starts `A server is a gateway`:
   ```
   "use <name> --key-of <server>" sends the new sessions that send <server>'s
   key to <name>, through the router's key_routes: map. One hop only. An
   agent's own server, from "use --agent", wins over it. "reset --key-of
   <server>", or "use <server> --key-of <server>", removes the entry.
   ```
10. **One PR.** The estimate is about 450 counted lines.

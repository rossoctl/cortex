**The release tarball** that `install.sh` installs is built with the `full` profile (`.github/workflows/release-binaries.yaml`, `full_tags=$(profile_tags full)`). So a laptop binary carries every plugin in `full`, but the default config runs only the four in the block above.

**Two ways to turn a plugin on, on a laptop:**
- `agentop script install <name>` adds a `script` slot to the pipeline (`cmd/agentop/cmd_script.go`). `agentop script list` shows the shipped scripts. `agentop script remove <name>` removes one.
- `agentop server add <name> <url> --main WORD --helper WORD` and `agentop server use <name> --agent <agent>` add the `inference-router` entry (`cmd/agentop/cmd_server.go`). Doc: `docs/inference-router-plugin.md`.
- Otherwise, edit `~/.cortex/config.yaml`. Cortex hot-reloads a pipeline change, so no restart is necessary.

**The laptop cpex build is removed.** For laptop policy, link `praxis-policy.md` (anchor `#move-from-the-cpex-plugin` for a former cpex user).

**Registration file form** (`core/plugins/all/plugins_toolprune.go`, exact):

```go

```

**Build with a profile:** `make cortex` builds `./bin/cortex` with the `full` profile (`PROFILE=full|lite|local`). The tags come from `go -C scripts/profile-tags run . <profile>`, which prints a comma-separated list.

### Shared check procedure (T1 and T3 use it)

```sh
W=<worktree root>
make -C "$W" cortex                          # ./bin/cortex, full profile
S=$(mktemp -d)
HOME=$S "$W/bin/cortex" --local --write-config
sed -i 's/4760\([0-4]\)/5760\1/g' "$S/.cortex/config.yaml"   # GNU sed
# edit $S/.cortex/config.yaml as the step says, then:
HOME=$S timeout 8 "$W/bin/cortex" --config "$S/.cortex/config.yaml" 2>&1 | tee "$S/boot.log"
```

Pass: the log has no line with `level=ERROR`, `unknown plugin` or `config`-validation failure before the timeout ends the process, and the log shows the pipeline with each expected plugin name.

# PPE 1/5: Build PPE into cortex-gateway (#1797)

Source: the plan in the body of issue #1797 (parent #1785). This file copies that plan
and adds the decisions that the issue leaves open. Each decision has its reason.

Base: `4f56abf78482d1458cfff5bc2aac77b880893d1e` (upstream `main`, 2026-11-13).
Branch: `feat/ppe-policy-1797`.

## Goal

Add one config field, `praxis.policy.config_path`. When the field is set and
`praxis.enabled` is true, `cortex-gateway` runs the Praxis `policy` filter on each
request that it gets from Cortex.

Scope limits (Hai, 2026-11-11, on #1785):

- Laptop only. The Go CPEX plugin and the `authbridge-cpex` image stay for Kubernetes.
- Do not port `observe_codes`, the principal `token_file`, `bypass_hosts`/`strict_hosts`
  or synthetic egress.
- Not in scope: MCP policy (#1798), decisions in rows (#1799), docs (#1800), other
  `policy-*` Cargo features, other filter options (`body_access`, `allow_private_idp`,
  `llm:`, `context_headers`), `agentop setup` flags.

## Facts from the spikes (2026-11-11)

- The `policy` filter reads `config_path` (string) and `body_access` (default
  `read_only`). Do not set `body_access`. With `read_write`, `cortex_observe` records an
  SSE completion two times.
- The filter must come after `cortex_observe`. Before it, a denied request writes a
  request row with no `inference` and no `capture`.
- Without the `policy-engine` feature, a config with `filter: policy` fails at start
  with `fatal: unknown filter type: 'policy'`.
- A denied request gets 403 and the header `X-Policy-Violation: <code>`.
- `Cargo.lock` adds about 46 packages (+642 lines). No existing version changes.
- **Toolchain:** `/opt/homebrew/bin/cargo` (1.94) is first on `PATH` on this host, and it
  ignores `praxis/rust-toolchain.toml`. It fails. Always run
  `rustup run 1.96.0 cargo ...` from `praxis/`. Toolchain 1.96.0 is installed.

## Decisions made for this plan

1. **Rust test is direct (T1).** `praxis/server/tests/gateway.rs` already starts the real
   binary through `start(flags, env, config)`. The new test uses it. Reason: the issue
   asks for a direct test when practical, and this one is.
2. **Reloader test file is `core/reloader/reloader_test.go` (T2).** The issue lists the
   test but not the file. `TestValidateReloadable_PraxisNeedsRestart` is at line 1304.
   Add the new case next to it.
3. **No change to the golden file.** `cmd/cortex/testdata/gateway.yaml.golden` comes from
   `praxisConfig()` in `gateway_test.go`, which has no policy. The golden must stay
   byte-identical. That is the "no change" test, together with an explicit check.
   `praxis/server/tests/gateway.rs` reads the golden too, so it must not change.
4. **Validation uses `os.Stat`, not a read.** Refuse an error from `os.Stat` and
   `IsDir()`. Do not parse the file (issue requirement 3).
5. **No validation when praxis is off.** `validatePraxis` already returns at its first
   line when `!cfg.PraxisEnabled()`. Put the policy checks after that line, so
   requirement 6 holds with no extra code.
6. **Docs are not in this PR.** #1800 owns them.

## Tasks

### T1: Rust features and a direct gateway test

Depends on: none.

Files:
- `praxis/server/Cargo.toml`: change the `praxis-proxy` features to
  `["pingora", "admin-api", "forward-proxy", "policy-engine", "policy-crypto-default", "policy-jwt", "policy-cel", "config-reload"]`.
  Do not add features to `praxis-proxy-filter` (Cargo feature unification gives them).
- `praxis/Cargo.lock`: regenerate with `rustup run 1.96.0 cargo build -p cortex-gateway`
  from `praxis/`. Commit it. Check that no existing package version changes
  (`git diff praxis/Cargo.lock` shows only added `[[package]]` blocks and added
  dependency lines).
- `praxis/server/tests/gateway.rs`: add `#[test] fn policy_filter_denies_a_model()`.
  - Write a policy file into a temp dir with this content:
    ```yaml
    routes:
      - llm: model-ok
        authorization:
          pre_invocation:
            - "llm.provider == 'never': deny('unreachable', 'never')"
      - llm: "*"
        authorization:
          pre_invocation:
            - "deny('model is not permitted', 'model_not_allowed')"
    ```
  - Write the policy file with `std::fs::write` into
    `std::env::temp_dir().join(format!("cortex-gateway-policy-{}", std::process::id()))`
    (create the dir first).
  - Call `start(&[], &[], |token_file, port| ...)` with the same `.replace` calls that
    `gateway_with` makes, except the last one: replace `{{ACCESS_LOG}}` with
    `format!("      - filter: policy\n        config_path: \"{path}\"\n{ACCESS_LOG}")`.
    This puts `policy` right after `cortex_observe` and before `access_log`.
    The origin answers each request with `respond(s, "200 OK", &[("Content-Type", "application/json")], b"{}")`.
  - Use the headers `fixture_headers()` plus `X-Cortex-Attribution`, as
    `inference_request_gives_request_and_response_lines` does. Send to
    `/v1/messages?beta=true` with the body
    `{"model":"model-bad","max_tokens":1,"messages":[{"role":"user","content":"hi"}]}`.
    Assert `status(&rh) == 403` and that the `x-policy-violation` header (match the
    name case-insensitively) is `model_not_allowed`. Then assert
    `o.seen.try_recv().is_err()` (the origin saw no request).
  - Send the same body with `"model":"model-ok"`. Assert 200, and assert
    `o.seen.recv_timeout(WAIT)` is `Ok`.

Tests: `rustup run 1.96.0 cargo fmt --check`,
`rustup run 1.96.0 cargo clippy --all-targets --locked -- -D warnings` and
`rustup run 1.96.0 cargo test --locked`, all from `praxis/`.

Estimated counted lines: 70 (`Cargo.lock` does not count).

### T2: Go config, validation, YAML and reload test

Depends on: none.

Files:
- `core/config/config.go`: add to `PraxisConfig`:
  `Policy *PraxisPolicyConfig \`yaml:"policy,omitempty" json:"policy,omitempty"\``.
  Add `type PraxisPolicyConfig struct { ConfigPath string \`yaml:"config_path" json:"config_path"\` }`
  with a one-line doc comment.
- `core/config/validate.go`, in `validatePraxis`, after the existing checks and before
  the address checks: when `cfg.Praxis.Policy != nil`, refuse:
  - an empty `config_path`: `praxis.policy.config_path: must be set when praxis.policy is set`;
  - a relative path (`!filepath.IsAbs`): `praxis.policy.config_path: %q must be an absolute path`;
  - an `os.Stat` error: `praxis.policy.config_path: %w` (wrap the error);
  - a directory: `praxis.policy.config_path: %q is a directory, not a policy file`.
  Each message starts with `praxis.policy.config_path`.
- `core/config/praxis_test.go`: one table test `TestPraxis_PolicyConfigPath` with the
  rows empty, relative, missing, directory (`t.TempDir()`), and valid (a file in
  `t.TempDir()`). Use the file's `praxisConfig()` helper with
  `Listener.BindLoopbackOnly = true`. Add `TestPraxis_PolicyIgnoredWhenOff`: praxis
  `Enabled: false` with `Policy{ConfigPath: "relative"}` passes `Validate`. Add a YAML
  parse check that `praxis: {enabled: true, policy: {config_path: /p.yaml}}` gives
  `ConfigPath == "/p.yaml"`.
- `cmd/cortex/gateway.go` (`gatewayYAML`): build the filter list in a slice. When
  `cfg.Praxis.Policy != nil && cfg.Praxis.Policy.ConfigPath != ""`, insert
  `{Filter: "policy", Opts: map[string]any{"config_path": path}}` right after
  `cortex_observe` and before `access_log`. When not set, the output does not change,
  byte for byte.
- `cmd/cortex/gateway_test.go`:
  - `TestGatewayYAML_PolicyOrder`: with `Policy.ConfigPath = "/p/policy.yaml"`, the
    filter order is `ip_acl, cortex_attribution, cortex_observe, policy, access_log,
    router, load_balancer`, and the `policy` entry has exactly the keys `filter` and
    `config_path`, with `config_path == "/p/policy.yaml"`.
  - `TestGatewayYAML_NoPolicyNoChange`: output with `Policy == nil` and with
    `Policy{ConfigPath: ""}` is `bytes.Equal` to the output of `praxisConfig()`. The
    golden test stays as it is.
- `core/reloader/reloader_test.go`: add `TestValidateReloadable_PraxisPolicyNeedsRestart`
  next to `TestValidateReloadable_PraxisNeedsRestart`. Add a policy, change the path,
  and remove the policy. Each one is refused with an error that contains `praxis.*`.
  The same policy on both sides passes. No change to `reloader.go`.

Tests: `GOWORK=off go -C core test ./config/... ./reloader/...` and

### T3: End-to-end tests

Depends on: T1 (the binary must know `policy`), T2 (`PraxisPolicyConfig` and the YAML).

File: `cmd/cortex/praxis_e2e_test.go` (build tag `praxis_e2e`).
- Add `policy string` to `chainOpts`: the policy file content. When it is not empty,
  `newPraxisChain` writes it to `<t.TempDir()>/policy.yaml` and sets
  `c.cfg.Praxis.Policy = &config.PraxisPolicyConfig{ConfigPath: path}` **before**
  `writeGatewayFiles`.
- `TestPraxisE2E_PolicyDeniesModel`: the policy is the YAML in T1. The origin serves
  an inference JSON response (use the helpers the file has, for example `serveJSON`).
  - Count origin requests as `len(o.headers)` under `o.mu`.
  - A request with `"model":"model-ok"` gets 200, and the origin count goes from 0 to 1.
  - A request with `"model":"model-bad"` gets 403 with
    `X-Policy-Violation: model_not_allowed`, and the origin count stays at 1.
  - Send each request with `c.client` as a POST to `chatURL` (the file's constant), with
    the body `{"model":"<model>","messages":[{"role":"user","content":"hi"}]}`.
  - `c.waitResponses(t, 2, ...)` finds two response rows.
- `TestPraxisE2E_NoPolicyNoChange`: `chainOpts{}`. A `"model":"model-bad"` request

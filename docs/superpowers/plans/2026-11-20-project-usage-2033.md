## Decisions made while planning

1. **Length limit for `project=`: use `event.MaxLabelLen` (96, `core/cost/event/sum.go:72`).**
   The issue says to export `maxLabelLen` from `core/cost/usage` as `MaxLabelLen`. That
   constant is already `= event.MaxLabelLen`, and `event.MaxLabelLen` is exported. So
   Task 4 adds `const maxProjectLabelLen = event.MaxLabelLen` in `core/sessionapi/usage.go`,
   beside `maxAgentLabelLen` (which has the same form), and exports nothing new from
   `core/cost/usage`. Reason: the same value, no new API in `core/`, which other repos
   consume. This replaces the issue's "export `maxLabelLen`" step in Task 4.
2. **Line numbers in the issue are approximate.** On base `8fa1fc9a`, `Record` is at
   `core/cost/usage/usage.go:959` and `Aggregator.agents` at `:839`. Find each place by name.
3. **Test helper names.** `core/cost/usage/project_test.go` already has
   `projectEvent(t, agent, project)`. `core/cost/ledger/project_test.go` has its own
   `projectEvent(t, when, project, costUSD)`. Reuse them. Do not declare a second one.
4. **The only caller of `(*ledger.Writer).Snapshot` outside tests is
   `core/sessionapi/usage.go:234`.** No interface wraps it, and no code in `cmd/` calls it.
   Task 3 updates that caller and the tests in `core/cost/ledger/` (`snapshot_test.go`,
   `project_test.go`) with a `""` project argument, so Task 3 compiles alone.
5. **One PR.** The estimated total is about 1,250 counted lines, under the 2,000 limit.
6. **Tasks 5–7 named in "Review Focus" are in #2034 and #2035**, not in this plan.
   Review Focus items 1 and 5 (agentop fallback, 80-column cell) are therefore out of scope
   here. Items 2, 3 and 4 are tested in T1 and T2.
7. **How `snapshot` reads a project ring (was "builder's choice").** Split
   `(*Aggregator).snapshot` in `core/cost/usage/snapshot.go` into two parts: `snapshot` takes
   `a.mu.RLock`, picks the ring as it does now, and calls a new
   `func (a *Aggregator) snapshotRingLocked(ring []bucket, window, resolution time.Duration, sessionID string, group Group, maxSeries int) Snapshot`
   that holds everything after the ring pick. `ProjectSnapshot` takes `a.mu.RLock` itself,
   runs `projectRingComplete`, and calls `snapshotRingLocked` with the project ring. If it
   falls to rule 3, it releases the lock before it calls `snapshot` (RWMutex read locks must
   not nest across a waiting writer). All existing callers keep their behaviour.
8. **The echo of `Agent` in rule 3.** When `sessionID == ""` and `agent != ""` (known),
   rule 3 reads the agent ring and sets `Agent = agent`. When `sessionID != ""` and the
   agent is known, rule 3 reads the session ring, which has no agent axis inside the
   project series, so it does NOT set `Agent` (absent means "not applied"). When the agent
   is not `""` and not known, rule 2 applies, with or without `sessionID`.

## Global Constraints

- Project ring cap: **32**, a constant (`maxProjectRings`), not config.
- Ring keys: `("", project)` for every event; `(agent, project)` only when `model.IsKnownAgent(agent)`.
- The project label is `projectLabel(e)` (ring) and `labelFor(r, usage.GroupProject)` (ledger). The server matches the label the client got from `group=project`, never a raw path.
- New wire field: `Snapshot.Project string \`json:"project,omitempty"\``. Set ONLY when the filter was applied. Absent means "not applied", the same contract as `Snapshot.Agent`.
- agentop never sends `project=Other` (`otherProjects`) or `project=(other)` (`projectOverflowLabel`).
- Out of scope: Sessions pane cost cell, `agentop cost --project`, new drawer axes.
- Every commit: `git commit -s`, message ends with `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`. PR titles `feat: <Uppercase subject>`. Each PR ≤ 2,000 lines.
- Before each push: `GOWORK=off go vet ./...` and `gofmt -l .` in each touched module (`core`, `cmd/agentop`).

## Review Focus

1. **An older proxy ignores `project=`.** It returns the agent's whole traffic with no `project` echo. agentop must fall back to client-side narrowing, never show it under the project label. Test: Task 5, `TestFetchUsageScopedProject_NoEchoFallsBack`.
2. **A project ring was evicted and comes back.** It has fewer minutes than the window. The server must serve the narrowed, group-none reply. Test: Task 2, `TestProjectSnapshot_EvictedRingIsServedNarrowed`.
3. **Startup replay with more than 32 projects.** The merge must keep the cap. Test: Task 1, `TestFinishReplay_KeepsTheProjectRingCap`.
4. **`project=` with an unrecognised agent on a ring window.** No agent×project data exists. The reply must not echo `project`. Test: Task 2, `TestProjectSnapshot_UnknownAgentDoesNotEcho`.
5. **An 80-column terminal with SERVER shown.** A mixed cell does not fit. It must show `(mixed)`, and AGENT must not get narrower than today. Test: Task 7, `TestAgentsPane_MixedCellFallsBackAt80`.

### Task 2: `ProjectSnapshot` and the completeness test

**Files:**
- Modify: `core/cost/usage/snapshot.go` (`Snapshot` struct near `:173`, `snapshot` at `:701`), `core/cost/usage/scope.go`
- Test: `core/cost/usage/project_snapshot_test.go`

**Interfaces:**
- Consumes: Task 1's `projects`, `projectKey`.
- Produces:
  - `Snapshot.Project string \`json:"project,omitempty"\``
  - `func (a *Aggregator) ProjectSnapshot(window, resolution time.Duration, sessionID, agent, project string, group Group) Snapshot`
  - `func projectRingComplete(ring, ref []bucket, project string, newest time.Time, n int) bool` — true when the ring's `Requests` over the newest `n` buckets equals the sum of `ref[i].byProject[project].Requests` over the same buckets.

Rules for `ProjectSnapshot`:
1. `sessionID == ""`, `agent` is `""` or known, the key has a ring, and `projectRingComplete(ring, ref, ...)` (ref = `a.all` for agent `""`, `a.agents[agent]` otherwise): read that ring through `snapshot`, honour `group`, set `Agent = agent`, `Project = project`.
2. `agent` is not `""` and not known (with or without `sessionID`): return `a.AgentSnapshot(window, resolution, sessionID, agent, group)` unchanged, `Project` NOT set.
3. Otherwise: `NarrowToLabel` of `a.snapshot(window, resolution, sessionID, refAgent, GroupProject, math.MaxInt)`, where `refAgent` is `agent` when `sessionID == ""` and `""` when `sessionID != ""` (the session ring). The result has `Group = GroupNone`; set `Project = project`, and set `Agent = agent` only when `sessionID == ""` and `agent != ""` (Decision 8).

How `snapshot` reads a project ring: Decision 7 (`snapshotRingLocked`).

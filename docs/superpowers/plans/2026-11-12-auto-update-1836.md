# Automatic updates for the laptop service (#1836) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local service install of Cortex checks for a new stable release once a day, installs it with no prompt after it has been Latest for 72 hours, and tells the user what happened.

**Architecture:** `agentop service install` writes a second unit (the updater) that runs `agentop update --yes --auto`. The proxy (`cmd/cortex`) starts that unit once a day with `launchctl kickstart` or `systemctl --user start`. `agentop update --auto` decides, installs through the existing installer path (`installRelease`), and writes `~/.cortex/update.json`. The TUI title bar and `agentop doctor` read that file.

**Tech Stack:** Go 1.26.10, launchd, systemd user units, `syscall.Flock`.

**Spec:** GitHub issue rossoctl/cortex#1836 (`gh issue view 1836 --repo rossoctl/cortex`). Its "Decisions" section is closed: do not reopen it. Read the issue before you start a task.

## Global Constraints

- Commit with `git commit -s`. End each commit message with `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`. No `Co-Authored-By`.
- Write comments in ASD-STE100 Simplified Technical English. Comment only the reason the code cannot show.
- Updater names: launchd label `io.rossoctl.cortex.update`, file `~/Library/LaunchAgents/io.rossoctl.cortex.update.plist`; systemd unit `cortex-update.service` in `~/.config/systemd/user/`.
- Status file `~/.cortex/update.json`, mode 0600, written with `writeFileAtomic`. Lock file `~/.cortex/update.lock`. Log `~/.cortex/update.log`.
- Plain-release regex: `^v[0-9]+\.[0-9]+\.[0-9]+$`.
- Delays: trigger waits 10 minutes after start, then wakes each hour; it runs the updater when the file is missing or its mtime is more than 24 hours ago, and at most once in 24 hours per process. Auto-install waits until the release is 72 hours old.
- Release time: the `Last-Modified` header of `https://github.com/rossoctl/cortex/releases/download/<tag>/checksums.txt`.
- `installRelease(env *setupEnv, ref string, flags []string, stdout, stderr io.Writer) error` in `cmd/agentop/cmd_update.go` is the seam with #1837. #1836 creates it by a move with no change in behavior, and after that only calls it. Do not change its body after T1.
- The proxy reads no config for this and makes no network call. Do not add `update` to `validateReloadable`.
- Windows is out of scope. agentop ships for darwin and linux only (no windows target in CI), so `syscall.Flock` without a build tag is acceptable.
- Run per-module Go commands with `GOWORK=off`. Always give `gofmt` a path.

## Review Focus

1. **The updater must not kill itself.** `agentop update --auto` runs inside the updater job, and it runs `agentop setup`, which runs `runServiceInstall`. If install does `launchctl bootout io.rossoctl.cortex.update`, the run dies before setup finishes. Rule: install never boots out the updater. It bootstraps the updater only when the label is not loaded. T3 has the test `TestServiceInstallNeverBootsOutTheUpdater`.
2. **A run that fails before it writes the file must not loop each hour.** T4 test `TestUpdateTriggerWaits24hAfterAStartWithNoFile`.
3. **A half-done swap (agentop v0.9.5, cortex v0.9.4) is not "current".** T5 test row `mismatch`.
4. **An empty `latest` (a manual `--ref=main` run, or a failed read) must not show "available".** T6 test `TestUpdateSuffixIgnoresEmptyLatest`.
5. **An install that predates this issue must get the updater unit at the next `agentop service install` / `agentop setup`**, not `Already current`. T3 test `TestServiceIsCurrentFalseWithoutUpdaterUnit`.

Behavior:

- `runAutoUpdate` follows the issue's step order exactly: (2) `latestRelease()` is `""` → `check-failed`, with `error: "could not read the newest release"`. (5) else `installReleaseFn(env, tag, updateFlags(env, "", true), stdout, stderr)` → `updated`, or `failed` with `Error = err.Error()` plus, on new lines, `lastLines(filepath.Join(env.cortexDir, "update.log"), 5)`.

**Interfaces:**
- Produces:
  ```go
  const updateStatusFile = "update.json"
  const (updateFirstWait = 10 * time.Minute; updateTick = time.Hour; updateEvery = 24 * time.Hour)
  type updateTrigger struct {
      file      string               // ~/.cortex/update.json
      now       func() time.Time
      start     func() error         // starts the updater unit
      lastStart time.Time            // zero: never
  }
  func (t *updateTrigger) tick() bool // true when it called start
  func startUpdaterUnit() error      // per runtime.GOOS
  func runUpdateTrigger(ctx context.Context, t *updateTrigger)
  ```

`tick`: due when `os.Stat(file)` fails, or `now().Sub(mtime) > updateEvery`; and `lastStart` is zero or `now().Sub(lastStart) >= updateEvery`. When due, set `lastStart = now()` before `start()`, then call it; a `start` error is logged with `slog.Debug` and ignored. `startUpdaterUnit`: darwin `exec.Command("launchctl", "kickstart", "gui/"+strconv.Itoa(os.Getuid())+"/io.rossoctl.cortex.update").Run()`; linux `exec.Command("systemctl", "--user", "start", "--no-block", "cortex-update.service").Run()`; other OS returns an error. `runUpdateTrigger`: wait `updateFirstWait` (or ctx done), `tick`, then `time.NewTicker(updateTick)` and `tick` on each tick until ctx is done. Compare wall clock times (`time.Now()` vs file mtime), never one 24h timer: a laptop sleeps.

In `main.go`: `if localInstall { if dir, err := defaultCortexDir(); err == nil { go runUpdateTrigger(ctx, &updateTrigger{file: filepath.Join(dir, updateStatusFile), now: time.Now, start: startUpdaterUnit}) } }`. Not behind `cfg.Pricing` and not behind any config field.

Content:
- laptop-service.md: on a service install (launchd or systemd), the proxy starts the updater unit (`io.rossoctl.cortex.update` / `cortex-update.service`) at most once a day, first 10 minutes after the proxy starts. The updater runs `agentop update --yes --auto`. It installs the release GitHub marks Latest once that release has been Latest for 72 hours, then restarts the proxy (attached sessions lose the request in flight and retry). It does not change `dev`, `main-<sha>`, release-candidate or `--no-service` installs; those get the notice only. A newer Latest shows on the title bar at once. Turn it off with `update: {auto: false}` in `~/.cortex/config.yaml`; the next run reads it, no restart. The result is in `~/.cortex/update.json`, the output in `~/.cortex/update.log`, and `agentop doctor` has an `updates` row. `agentop update` by hand still installs at once, with no 72-hour wait.
- README: `--auto`: what the daily updater runs; implies `--yes`; never asks. Title-bar notices, in order: `· updated to vX.Y.Z, restart agentop`, `· update to vX.Y.Z failed, see agentop doctor`, `· vX.Y.Z available`, `· no update check since <date>` (service installs only, after 72 hours with no check).
- CONTRIBUTING kill switch: to stop a bad release, mark the previous release as Latest on GitHub. Auto-updaters that installed the bad release go back at their next run, within 24 hours. The others never install it, because it is no longer Latest. The 72-hour delay gives time to do this before most users install it.

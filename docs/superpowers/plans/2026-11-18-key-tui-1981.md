# agentop TUI switches the server for a key from S (#1981) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the sessions pane, `S` can also send the new sessions that send a key to the chosen server (`key_routes:`). On the agents pane, `S` shows which server each session goes to by its key. agentop never shows a key: it names a key by the name of its server.

**Architecture:** The session summary gets `inferenceKeyOf` (the router's `key_of` detail; PR #1986 left it out because it had no reader). The sessions-pane picker gets a second step when that field names a configured server. Row 2 of that step writes `servers.SessionChanges` and `servers.KeyRouteChanges` in one `edit.WritePluginConfig`. The agents-pane picker renames its first row and adds a muted count line under it.

**Tech Stack:** Go 1.26.10. Modules `core/` and `cmd/agentop/`.

**Spec:** issue rossoctl/cortex#1981 (part C2 of #1975). Read it with `gh issue view 1981 --repo rossoctl/cortex`. Parts A1, A2, B (#1979, PR #1986) and C1 (#1980) are merged into the base of this plan. B's plan, `docs/superpowers/plans/2026-11-18-key-selects-server-1979.md` Task T1, describes `inferenceKeyOf`. Task T1 below implements it.

## Global Constraints

- A key is never shown, logged or written into a flash. agentop names a key only by its server's name.
- `key_routes:` is one hop only: with `{team-b: team-a, team-a: team-c}`, team-b's key goes to `team-a`.
- Row 2 does not move other running sessions. It changes only new sessions.
- Every served string that is drawn goes through `sanitizeLabel`, as the code around it does.
- Comments and docs in ASD-STE100 Simplified Technical English. Commits use `git commit -s` and end with `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`.
- Go commands per module with `GOWORK=off`. `gofmt -l <path>` always with a path.
- Tests assert on substrings, as the existing tests in `tui/server_picker_test.go` do.

## Decisions made in this plan

1. **T1 adds `InferenceKeyOf` to the summary here.** PR #1986 deferred it to its first reader, and this issue is that reader. T1 follows B's plan Task T1, with one change: no `pipeline.RoutedKeyOf` wrapper. Reason: no plugin reads it, and API lands with its caller.
2. **The second step opens only on a server row, not on row 0 ("its own choice").** Reason: `key_routes:` has no value for "not routed". `KeyRouteChanges(k, "")` removes the entry, which sends the key to its own server: that is not what row 0 means.
3. **"Names a configured server"** means `router.Servers[string(summary.InferenceKeyOf)]` exists in `m.activeRouter()` when the picker opens. Else the picker stays one step.
4. **Row 1 of the second step is the cursor's start.** Reason: it is today's behavior, so Enter Enter does what Enter did before.
5. **Keys in the second step:** up/k, down/j, home/g, end/G move; enter applies; esc and q go back to the server list with its cursor where it was; ctrl+c closes the picker and writes nothing. Reason: the issue asks for Esc to go back; ctrl+c stays the "leave now" key.
6. **The "stay on" note.** N counts the sessions `s` in `m.sessions` with `s.ID != p.session`, `s.Resident` nil or true, `s.InferenceHost != ""` (the `sessionsStaying` filter), `s.InferenceKeyOf == keyOf`, and `servers.ForSession(router, s)` == keyOf. Text: ` (1 other running session stays on team-b)` or ` (N other running sessions stay on team-b)`. Left out when N = 0 and when the target is keyOf itself (then nothing goes elsewhere). Computed when the picker opens, as `sessionsStaying` is computed at enter.
7. **The "ignores this" note** replaces the "stay on" note when `router.Agents[p.agent] != ""`: ` (claude-code ignores this: the Agents pane sends it to ete)`. Reason: an `agents:` entry wins over `key_routes:`, so the stay count does not apply to this agent's sessions.
8. **The flash for row 2** appends one sentence to the session's flash on `WriteReloaded` and `WriteUnchanged`: ` New sessions that send team-b's key → team-a.` When the target is keyOf: ` New sessions that send team-b's key go to team-b.` Other outcomes keep the session text unchanged, because they already say where the file was left.
9. **Row 0 label split.** `ownChoiceEntry` becomes `"Each terminal's key decides"` and is used only in the agents picker. A new constant `sessionOwnChoiceEntry = "its own choice (not routed)"` keeps the sessions picker's row 0. Reason: for one session, `""` sends it to its own provider, not "by key".
10. **The agents-pane count line** is computed when the picker opens and is drawn muted under row 0, indented 4 spaces. It counts the sessions in `m.sessions` with `pipeline.AgentName(s.Agent) == p.agent`, `s.Resident` nil or true, and `s.InferenceKeyOf` naming a configured server. Each goes to `router.KeyRoutes[k]` when set, else `k` (one hop). Groups sort by count descending, then name. Format: `now: 2 sessions → team-b, 1 → team-a`; the first group says `1 session` or `N sessions`, the rest say only the number. With no such session: `no session sends a known key now`.
11. **`agentOwnChoice` becomes `"by key"`.** It fits `agentsServerWidth` (12). `sameRouter` does not change: the SERVER cell does not read `KeyRoutes`.
12. **README line 1268 of the issue** is now around lines 1278-1281 (`confirming what the move costs first`). T4 replaces that phrase.

## Review Focus

1. A session whose `InferenceKeyOf` names a server that was removed after the session ran: the picker must stay one step (T2 test `TestServerPicker_AnUnknownKeyOwnerIsOneStep`).
2. Target == keyOf on row 2: the write must remove `key_routes.<keyOf>`, never write `team-b: team-b` (T2 test `TestServerPicker_RowTwoToTheKeyOwnerRemovesTheEntry`).
3. A server name with an escape sequence in the note or flash: must be sanitised (T2 extends `TestServerTexts_DrawNoControlFromWhatTheProxyServed`).
4. Esc on step 2 must not close the picker or write anything (T2 test `TestServerPicker_EscOnTheSecondStepGoesBack`).
5. A `key_routes:` entry whose target is itself routed (two hops): the agents count line must stop after one hop (T3 test `TestServerPicker_TheKeyCountIsOneHop`).

# Plan: set MCP metadata in cortex_observe for the policy filter (#1798)

Issue: https://github.com/rossoctl/cortex/issues/1798 (PPE 2/5, parent #1785).
Base: `main` at `7384d369b6ad98a43b3535968e25cf3b747fffdd`. #1797 is merged
there (PR #1842), so this PR has no parent PR.

The task list comes from the issue body. This file adds the decisions that
the issue leaves open.

## Goal

The Praxis `policy` filter reads `filter_metadata` keys `mcp.method` and
`mcp.name`. When `mcp.method` is missing on a JSON-RPC request, it returns
HTTP 500 (`config.missing_protocol_metadata`). `cortex_observe` runs before
`policy` in the chain (#1797). It parses MCP already. It must write the two keys.

## Decisions

1. **The parse result comes from the `Exchange`.** Add one accessor in
   `praxis/filters/src/record/row.rs`:

   ```rust
   /// The MCP request that `on_request_body` parsed, if any.
   pub fn mcp(&self) -> Option<&McpExtension> {
       self.observers.mcp.as_ref().and_then(McpObserver::extension)
   }
   ```

   `request_row` clones the MCP extension and takes nothing from it, so the
   row does not change. The body is parsed one time.

2. **A pure function picks the keys.** In
   `praxis/filters/src/filters/observe.rs`:

   ```rust
   fn mcp_metadata(ext: &McpExtension) -> Vec<(&'static str, &str)>
   ```

   Rules, in this order:
   - `ext.method` starts with `$` (a synthetic `$transport/stream` or
     `$transport/terminate` row from a bodyless GET or DELETE): return nothing.
     That request is not JSON-RPC.
   - Push `("mcp.method", ext.method)`.
   - For `tools/call` and `prompts/get`: push `("mcp.name", params.name)`.
     For `resources/read`: push `("mcp.name", params.uri)`. Only when the
     param is a JSON string. Other methods get no `mcp.name`.
   - Drop each value longer than 256 bytes (`MAX_METADATA_VALUE`, a local
     `const` = 256). Code comment: `set_metadata` also refuses such a value,
     but a dropped key is the safe result: the policy filter then fails
     closed (500 or deny), and a truncated name could match an allow rule.
     The keys are 12 and 8 bytes, under the 64-byte key limit.

   Reason for a pure function and not a test `HttpFilterContext`: the
   upstream context builder (`make_filter_context`) is `pub(crate)`, and a
   copy of its 25 fields breaks on each Praxis bump. The e2e test (T2)
   proves the wiring into the context.

3. **The wiring.** In `on_request_body`, at end of stream, inside the
   existing `if let Some(s) = state(ctx)` block: compute `line`, then
   collect `mcp_metadata(...)` into owned `(&'static str, String)` pairs
   while the lock is held, release the lock, submit the line, then call
   `ctx.set_metadata(k, v)` for each pair. A request with no `State` (no
   valid token) sets nothing: `cortex_attribution` already refused it.

4. **Batch and non-JSON bodies set nothing.** `jsonrpc::decode_request`
   returns `None` for a body that does not start with `{`, so `parse_request`
   returns `None` and `mcp()` is `None`. No extra code.

5. **The e2e policy** (T2). Same shape as `e2ePolicy` in
   `cmd/cortex/praxis_e2e_test.go`:

   ```yaml
   routes:
     - tool: safe_tool
       authorization:
         pre_invocation:
           - "http.method == 'NEVER': deny('unreachable', 'never')"
     - tool: "*"
       authorization:
         pre_invocation:
           - "deny('tool is not permitted', 'tool_not_allowed')"
   ```

   If the policy filter refuses this file at load, change only the
   `safe_tool` rule to another rule that never denies, and say so in the
   PR body.

## Tasks

### T1: write the MCP metadata

Depends on: none.

Files:
- `praxis/filters/src/record/row.rs`: add `Exchange::mcp` (Decision 1).
- `praxis/filters/src/filters/observe.rs`: add `mcp_metadata`, the length
  `const`, the wiring (Decisions 2, 3), and a `#[cfg(test)] mod tests` at
  the end of the file.

Tests (in `observe.rs`, build `McpExtension` from
`crate::parse::mcp::parse_request("POST", "/mcp", &HeaderMap::new(), body)`
so that the test uses the real parser):
- `tools/call` with `name: "safe_tool"` gives `mcp.method = tools/call`
  and `mcp.name = safe_tool`.
- `prompts/get` gives `mcp.name` from `name`.
- `resources/read` gives `mcp.name` from `uri`.
- `tools/list` gives only `mcp.method`.
- `tools/call` with a name of 300 bytes gives only `mcp.method`.
- `tools/call` with `name: 1` (not a string) gives only `mcp.method`.
- A synthetic `$transport/stream` extension gives nothing.
- A batch body `[{"jsonrpc":"2.0",...}]` and a body `not json`: `parse_request`
  returns `None` (assert it, so that the "sets nothing" rule is pinned).

Estimate: 90 counted lines.

### T2: end-to-end test

Depends on: T1.

File: `cmd/cortex/praxis_e2e_test.go` (build tag `praxis_e2e`).

Add `const e2eToolPolicy` (Decision 5) and
`TestPraxisE2E_PolicyDeniesTool`, after `TestPraxisE2E_PolicyPassesNonInference`.
Use `newMockOrigin`, `origin.serve(serveJSON(...))`,
`newPraxisChain(t, origin, chainOpts{policy: e2eToolPolicy})`, `c.do`,
`origin.count()` and `request(...)` as the existing policy tests do. URL:
`http://mcp.example.com/mcp`. Bodies are JSON-RPC 2.0 with `id` 1, 7 and 3.
Expected:
- `tools/call` `safe_tool`: status 200; the origin count goes to 1.
- `tools/call` `danger_tool`: status 200; `X-Policy-Violation:
  tool_not_allowed`; the body decodes to a JSON-RPC error with
  `error.code == -32001` and `id == 7`; the origin count stays 1.
- `tools/list`: status 200; the origin count goes to 2.

The existing `TestPraxisE2E_PolicyPassesNonInference` (an `llm:`-only policy
with an MCP `tools/call`) must still pass.

Estimate: 60 counted lines.

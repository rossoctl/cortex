# agentop: dashboard layout with a boxed body and one bottom bar (#2020) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make each agentop pane one panel: the title, then a rounded box with the spend band in its top edge and the pane body inside, then one bottom bar with the keys on the left and the status on the right.

**Architecture:** All work is in `cmd/agentop/tui`. A new file `box.go` draws the box edges and frames a body to an exact height and width. `layout()` reserves the box rows. `paneView` frames every pane body with the box, so the body is always `m.bodyHeight` rows and the bar is always on the last row. `footerView` becomes one line. Pane bodies render at the inner width `m.innerWidth()`.

**Tech Stack:** Go 1.26.10, Bubble Tea v1, Lip Gloss v1.1.0, `github.com/charmbracelet/x/ansi` v0.11.9 (it has `ansi.Cut` and `ansi.TruncateLeft`). Add no dependency.

**Spec:** issue #2020 (`gh issue view 2020 --repo rossoctl/cortex`). Read it in full before you start a task. Where this plan and the issue differ, the issue wins, except for the items under "Decisions". The mockups named in the issue are on the author's machine only (`~/Documents/agentop-mockups/`). Do not depend on them.

**Base:** part 1 (#2019) is merged into `main`, so this branch starts from the upstream `main` tip `bba66454753587378b12f44636f9d6ffa861f772`.

## Global Constraints

- The 9 rules of the issue's "Rules that stay from #2015 and part 1" apply to every task. In short:

  2. Table cells keep no ANSI.
  3. Search highlighting, marked rows and the selected-row tint keep working.
  4. A cell style sets only foreground and bold.
  5. Each new color is a `lipgloss.AdaptiveColor` in `styles.go`. (This plan adds no new color: the box uses `colorDim`.)
  6. Under the Ascii profile (what `go test` gets), keys keep their brackets, and there is no bar or chip. The box glyphs are drawn under Ascii too.
  7. No regression of more than 10% in `BenchmarkRebuildEventsTable`, `BenchmarkRebuildEventsTableTrueColor` and `BenchmarkEventsTableView` (`tui/events_rebuild_bench_test.go`).
  8. The key grammar (`tui/key_grammar_test.go`) holds.
  9. Rows add up: the view is exactly as tall as the terminal. Change the reservation tests only for the row and column costs this plan names. Each task writes, in its final commit message, a list of every test it changed and why. The PR body copies these lists.

## Decisions (made here, with the reason)

1. **One PR.** The estimate is about 1,560 counted lines (see "PRs"), under 2,000. Reason: the size rule.
2. **Change 3 goes into T1.** The box frames the body to exactly `m.bodyHeight` rows: it pads a short body with blank framed rows and cuts a tall body at `m.bodyHeight`. So padding (change 3) and framing (change 1) are one function, written once in `paneView`. Reason: the issue says to fix it once where `paneView` joins the body and the footer, and the box is that join.
3. **Usage fix (T1).** Usage is too tall because its renderer does not follow `bodyHeight` (the comment by `fitModel`'s usage snapshot, `layout_fit_test.go:98-111`). The box cut (Decision 2) is the fix: at 60×20 the bottom rows of the Usage body (the summary and the `updated … ago` line) are cut, and the bar stays on the last row. Also pass `m.innerWidth()` and `m.bodyHeight` to `renderUsage`. Remove the `paneUsage` skip in `TestLayout_EveryPaneFitsTheTerminal` and update the fixture comment. Reason: a pane that is too tall pushes the bar off the screen, and a cut body keeps the bar. A smaller chart at small sizes is a separate change, and the issue does not ask for it.
4. **`box.go` API (T1).** New file `cmd/agentop/tui/box.go`, which replaces `divider.go` (delete `divider.go` and `renderDivider`; rename the reservation constant):
   ```go
   const (
       boxSideCols = 2 // the │ on each side
       boxTopLines = 1 // the top edge (replaces dividerLines)
       boxBottomLines = 1
   )
   // boxTop is ╭─…─╮ across width, with label (already styled, already fitted) after "╭─ " when label != "".
   func boxTop(label string, width int) string
   // boxBottom is ╰─…─╯ across width.
   func boxBottom(width int) string
   // boxFrame frames body: exactly height lines, each "│" + the line cut (truncToWidth) or padded with spaces to width-2 + "│".
   func boxFrame(body string, width, height int) []string
   // innerWidth is the width a pane body renders at.
   func (m *model) innerWidth() int { return max(m.width-boxSideCols, 0) }
   ```
   - The glyphs `╭ ─ ╮ │ ╰ ╯` are rendered with `styleDim`. The label keeps its own styles.
   - With a label: `"╭─ " + label + " " + "─"*k + "╮"`, with `k >= 1`. So the label gets at most `width - 6` columns. The caller fits the label to that width before it styles it.
   - `width < 2`: every function returns `""` (or `height` empty strings for `boxFrame`). No panic at any width.
   - Padding counts columns with `lipgloss.Width`, so a styled line pads right (rule 1).

10. **One bottom bar (T2).** `footerView` returns ONE line, built by a new pure function in `footer.go`:
    ```go
    // bottomBar lays hints out on the left and status on the right of one line of width columns.
    // hints is helpView(); status is the styled status, already in bar ink.
    func bottomBar(hints, status string, width int) string
    ```
    - `essential = "[?] keys  [q] quit"`. Every `helpView` string ends with it (check: `TestFitHintLine_KeepsQuitAndHelpAtEveryWidth`). Room for the status: `statusRoom = width - lipgloss.Width("… "+essential) - 2`. When `statusRoom < 1`, the status is not drawn.
    - The status is cut from the RIGHT to `statusRoom` with `truncToWidth` (ANSI-aware, rule 1). The status is ordered: connection state first, then the other notes, then a non-sticky flash. So a cut drops the flash first, then the notes, and the connection state last.
    - The hints get `width - lipgloss.Width(status) - 2` (2 = a gap) and go through `fitHintLine` (drops from the left, keeps `[?] keys  [q] quit`).
    - The line: `renderKeyBar(fittedHints, 0)` + a bar-colored gap + the status, padded so the status ends on column `width`. Under color, every gap and pad is `styleBar` spaces, and each status run has `Background(colorBarBg)` added to its style (`styleOK`, `styleWarn`, `styleError`, `styleMuted`, `styleTitle` used in the status). Under Ascii there is no background and the pad is plain spaces. `lipgloss.Width(line) == width` when `width > 0`.
    - Rate (`N events/sec`), `[paused]`, the server switch, the search status, the two scope notes and the sort note are "other notes", in today's order, joined with three spaces as today.
    - **Sticky flash:** the status is the connection state, then `"   "`, then `fitFlashLine(m.flash, room)` where `room = statusRoom - width(connection state) - 3`. The other notes go, and the hints go except `essential`. If `room < 2`, the connection state goes too and the flash gets all of `statusRoom`. Reason: the issue keeps `? keys  q quit` first and the connection state second, and a flash is cut from the left as `fitFlashLine` does.
    - Delete `fitStatusLine` if nothing calls it after this change.

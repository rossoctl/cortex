# Agents Pane: Scope Views to a Project (#1818) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enter on a project sub-row of the AGENTS pane narrows the sessions list, the usage pane, the spend band and the drawer to that project (under its agent, or under All agents).

**Architecture:** A second scope `m.projectScope` beside `m.agentScope`. No server change: every project-scoped usage read asks for `group=project` (agent-scoped when an agent is set) and the client narrows the reply to one series with a new `usage.NarrowToLabel`. The sessions list filters on `SessionSummary.Projects`. Everything else is in `cmd/agentop/tui/` plus the README.

**Tech Stack:** Go 1.26.10, Bubble Tea, `core/cost/usage`.

**Spec:** https://github.com/rossoctl/cortex/issues/1818 (its "Decisions" 1-3 are fixed; this plan cites them as D1..D3). Parent #1739. #1815, #1816 and #1817 (PR #1824: sub-rows, `agentRowDesc`, `otherProjects`, `projectDisplayNames`, `foldSeriesInto`, `namedProject`) are merged into the base.

## Decisions made in this plan (not in the issue)

1. **`NarrowToLabel` in core.** `usage.NarrowToAgent` is axis-agnostic except that it writes `Agent = agent`. Add `func NarrowToLabel(snap Snapshot, label string) Snapshot` with today's body less the `Agent` line, so it KEEPS `snap.Agent` (the agent echo of an agent-scoped read). `NarrowToAgent` becomes `s := NarrowToLabel(snap, agent); s.Agent = agent; return s`. A label with no series gives zeroed buckets, not an error (the same as `NarrowToAgent` today).
2. **One narrowing helper in the TUI.** `narrowToProject(snap *usage.Snapshot, project string) *usage.Snapshot`: for `otherProjects` it first runs `foldSeriesInto(snap, namedProject, otherProjects)`, then `usage.NarrowToLabel`. `fetchUsageScopedProject(ctx, client, window, resolution, agent, project, group)` is `fetchUsageScoped(..., agent, group)` when `project == ""`, else `fetchUsageScoped(..., agent, usage.GroupProject)` then `narrowToProject`. The band, the drawer and the usage pane all use these two, so the band total and the sub-row COST come from the same fold.
3. **Usage pane within one session.** Under a project scope with `m.usage.session != ""`, `readUsage` reads `client.GetUsage(window, resolution, session, usage.GroupProject)` with no agent, then narrows. Reason: the server answers `agent=` within a session from the agent axis, which has no project series, and a session in the scoped list already belongs to the scoped agent (`sessionListed`).
4. **Usage pane latency under a project scope.** No per-project latency exists. The existing "latency is not available per agent" branch also fires under a project scope, and prints `(latency is not available per project)` with the line `Response times are recorded per agent, not per project.` instead of the per-agent reasons. `graftAgentLatency` is not called under a project scope.
5. **Spend band split.** Under a project scope the band does not make the second `GroupCurrency` read (`fetchSpendSpan`): the narrowed reply has no currency series. A mixed-unit cell then reads `money.Mixed`, as it does when the split fails today.
6. **Drawer under a project scope.** `spendAxes()` returns `nil`. `cycleSpendAxis` returns nil when `len(m.spendAxes()) == 0` (`a` is inert). `renderSpendDrawerAxes` leaves out the `[a] …` figure when `len(axes) == 0`. `spendAxis()` is unchanged (the fetch ignores it under a project scope). `drawerScopeNote` gains a `project string` parameter: when `project != ""` and `snap != nil`, it returns `"no breakdown for this scope in " + windowLabel`. The drawer passes `m.spend.drawerProject`.
7. **Band and drawer state.** `spendState` gains `bandProject` and `drawerProject` beside `bandAgent` and `drawerAgent`, set at fetch time and cleared where `drawerAgent` is cleared (`spend.go:~291`). `syncSpendScope` compares agent AND project.
8. **`spendScopeProject()`** sits beside `spendScopeAgent()` in `spend.go`. On the agents pane: `d.project` on an `agentRowProject` row, `otherProjects` on an `agentRowProjectOther` row, `""` on any other row. Elsewhere: `m.projectScope`.
9. **Display name in titles.** `func (m *model) projectScopeName(agent, project string) string`: `otherProjects` gives `"Other"`; when `m.agentProjects[agent]` is loaded, the name `projectDisplayNames` gives for `project` among that row's named labels (the same rule as the sub-row cell); else the last `/` segment of `project` (`"~"` stays `"~"`). One title helper `func (m *model) scopeSuffix(agent, project string) string` returns `" · agent=" + sanitizeLabel(agent)` when `agent != ""`, then `" · project=" + sanitizeLabel(m.projectScopeName(agent, project))` when `project != ""`. All five title sites use it.
10. **Sessions filter signature.** `sessionListed(s, agent, project string) bool` and `sessionsListTwoAgents(agent, project string) bool`. Project test: `""` passes; `otherProjects` needs `len(s.Projects) == 0`; else `slices.Contains(s.Projects, project)`. `clear.go:164` passes `project ""`: `x` erases the whole agent (#1817 D9).
11. **`sessionsProjectScope()`** in `agent_scope.go`, beside `sessionsScope()`: `""` when `m.projectScope == ""` or `!m.sessionsNameProjects()`, else `m.projectScope`. The sessions table filters with `(m.sessionsScope(), m.sessionsProjectScope())`. The footer (`footer.go:86`) adds `[no session names its project: list not scoped]` on the sessions pane when `m.projectScope != "" && m.sessionsProjectScope() == ""`.
12. **Empty sessions text** (`app.go:~2633`): shown when `(m.sessionsScope() != "" || m.sessionsProjectScope() != "") && len(m.sessionRowIDs) == 0`. Text: `"(no session belongs to " + rest + ")"`, where `rest` is the sanitized agent, then ` · project=<display name>` when a project scope is set. With no agent, `rest` is `project=<display name>`.
13. **"Marks its sub-row".** Today no glyph marks the committed agent row (`rebuildAgentsTable` reads no `agentScope`), so this plan adds no glyph. What the reader sees is the cursor: `enterAgents` and `returnToAgentsPane` call `m.revealProjectScope()` before `rebuildAgentsTable`. When `m.projectScope != ""` and `m.agentRowExpandable(m.agentScope)`, it sets `m.agentsExpanded[m.agentScope] = true` and puts the cursor on the committed sub-row through `m.agentsCursorWant` / `m.agentsCursorWantAt = m.agentsTbl.Cursor()`, so the cursor lands there when the projects reply arrives. The fetch comes from the existing `fetchOpenProjectsCmd` in the `agentRowsLoadedMsg` arm (`enterAgents`) and from the `fetchAgentRowsCmd` that `returnToAgentsPane` returns.
14. **Enter on a sub-row.** `keys.go` Enter arm (`case "enter", "right", "l"`, so `→` and `l` get the same change) reads `m.selectedAgentRow()`: `agentRowProject` sets `(d.agent, d.project)`; `agentRowProjectOther` sets `(d.agent, otherProjects)`; every other kind sets `(d.agent, "")`. The footer's `[↵]` text on a project or project-Other sub-row is `[↵] scope to this project`.
15. **No `project=` pin.** Both recording test servers (`cursorScopeModel` and `projectsModel`) call `t.Errorf` when a request has a `project` query key, so every test that uses them pins D3.

## Review Focus

1. **Enter on a project, then Enter on an agent row** must clear the project scope, or the next agent's list is narrowed to a project of the old agent — test `TestProjectScope_EnterOnAnAgentRowClearsTheProject` in T2.
2. **A project scope against sessions that record no project** must not empty the list — `sessionsProjectScope()` returns `""`; test `TestProjectScope_NoSessionNamesAProjectListsEverything` in T2.
3. **A project label with control characters** in a title — every title passes through `sanitizeLabel`; test `TestProjectScope_TitlesNameTheProject` in T2 uses a label with `\x1b`.
4. **The scope's project has no traffic in the band's window** — the band shows the zero/dash cell, not an error and not the agent's figure; test `TestProjectScope_BandOnAProjectWithNoTrafficIsEmpty` in T4.
5. **`a` on the drawer under a project scope** must not panic (`axes` is empty, `% len(axes)`) — test `TestProjectScope_DrawerAxisKeyIsInert` in T4.

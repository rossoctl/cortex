## Global Constraints

- **Module root is `authbridge/`.** Go commands run from `authbridge/`, relative to the repo root; `git` from the repo root itself.
- **`git commit -s` mandatory.** Trailer `Assisted-By: Claude (Anthropic AI) <noreply@anthropic.com>`; never `Co-Authored-By`.
- **abctl computes nothing.** No multiplication of tokens by rates, no dollar arithmetic beyond dividing published micros by 1e6 and computing percentages of a published total. ## Ruling made during planning: a third poll chain, deliberately

This pane needs its own window and grouping, so it needs its own snapshot. That makes **three** poll chains in the TUI — the Usage pane's, the spend strip's, and this one — each with the same sequence-guard shape.

Extracting a shared poller is the obvious response and is **deliberately not done here.** Refactoring the existing Usage pane's polling while simultaneously adding a pane means any regression in the Usage pane gets attributed to the new one, in the last commit of an eight-commit PR. Add the third copy, mark it, and file the extraction as its own focused change with the existing tests as its proof.

Copy the guard shape faithfully — `reqSeq` for stale replies, `tickGen` for stale chains. `usage_pane.go:64-79`'s comment records the bug it prevents: a quick exit and re-entry left two chains alive, each rescheduling the other's successor and doubling the request rate for the life of the session.

### The section that changed, and why — read before writing anything

The original design had **WHERE THE MONEY GOES**: four token tiers with a dollar figure each, summing to the total. **That cannot be built honestly on this tree, and must not be faked.**

- `usage.Counts` aggregates the four-way **token** split. That part is real, exact, and already there.
- It aggregates **no** per-tier dollars. Nothing does.
- The record carries `PromptUSD` and `OutputUSD`, but they are *modelled* figures, and `PromptUSD`'s own doc is explicit that when the total came from a gateway header "PromptUSD + anything is not a total of anything". `OutputUSD` likewise warns it is "not CostUSD minus PromptUSD", because that difference mixes a possibly-authoritative total with a modelled part.

So a four-tier dollar breakdown that sums to the total would be an invented number, and a prompt-versus-output dollar split would silently fail to reconcile with the total on exactly the deployments whose figures are most trustworthy — the ones with a gateway header.

**What the section shows instead:** the **token** split as shares, labelled as tokens, with no dollar figures. That answers a real and useful question — where the volume went, and therefore which tier is driving the bill, since the tiers price ~1x / 1.25x / 0.1x / output — while claiming only what is measured.

If a dollar breakdown is wanted later, the honest route is to aggregate `PromptUSD`/`OutputUSD` into `Counts` **and** disclose that they do not reconcile with an authoritative total. That is a separate change with its own argument; do not smuggle it in here.
